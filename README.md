# 間 MA — 展覧会プランナー

添付の「1/100」表記の建築図面と室内写真2枚に基づく、ブラウザーで動く3D・平面・WebXR展示計画アプリです。React 19 / Three.js / Vite 8。建築形状・作品配置を同じmm単位データから生成し、3Dと平面が一致する構成です。

## 公開版（GitHub Pages）

**[シミュレーターを開く](https://nbbbnbbb.github.io/exhibition-simulator/)** — インストールやローカルサーバーの起動は不要です。

作品・画像・プランは、利用しているブラウザーのIndexedDBに自動保存されます。「クラウド保存」ではGitHubのリポジトリにも保存でき、保存リストからの読み込み・上書き・URL共有に対応します。共有URLは保存時点のデータを開き、上書き後は同じURLで最新の保存状態を開きます。JSONの「書き出す」「開く」でも移行できます。

`.github/workflows/pages.yml` がプルリクエストでテスト・ビルドを行い、`main` への反映後にGitHub Pagesへ自動公開します。公開設定はリポジトリの Settings → Pages → Source を **GitHub Actions** にします。ソースコードと同梱資料も公開リポジトリから閲覧できます。

通常のローカルビルドは `/`、Actionsのビルドは `VITE_BASE_PATH=/exhibition-simulator/` を使います。画像・図面もこのパスに追従します。公開版と同じ構成を手元で確認する場合：

```powershell
$env:VITE_BASE_PATH = '/exhibition-simulator/'
npm run build
Remove-Item Env:VITE_BASE_PATH
npm run preview
# http://127.0.0.1:4173/exhibition-simulator/ を開く
```

## 起動

Node.js 22.12以降（または20.19以降の20系）（この環境では24.18）を使用します。

```powershell
cd 'C:\Users\BBB\Documents\ChatGPT\展覧会シミュレータ'
npm ci
npm run build
npm start
```

[http://127.0.0.1:5173/](http://127.0.0.1:5173/) を開きます。依存関係は導入済みなので、通常は `npm start` だけで起動できます。停止はサーバーを起動したターミナルで Ctrl+C、バックグラウンド起動中なら別ターミナルから `npm stop`。開発時は `npm run dev`（自動更新あり）を使います。同じポートを使うため、切り替える際は先に一方を停止してください。

本番用の静的ファイルを生成する場合：

```powershell
npm run build
npm run preview
```

表示されるURLを開いてください。ファイルを直接ダブルクリックする `file://` 起動には対応しません。自動保存領域はブラウザーとURLのオリジン（ホスト・ポート）ごとに別です。`localhost` と `127.0.0.1` 間の移行や別ブラウザーへの移行にはJSONを使用してください。

## 使い方

1. 左の「作品を登録」で作品名・作家・制作年・属性・サイズ原文・号数／形式・梱包サイズ・備考・点数・展示方法を登録します。画像と実寸は未入力でも保存できます。配置用の幅・高さ・厚みは、額を含む**1点あたりのmm**です。厚みの初期値は40 mm。JPEG / PNG / WebP画像（任意）は30 MB以下、最長2,048 pxに縮小して保存します。変更は全プランへ反映されます。
2. 作品カードの＋で追加モードに入り、3Dまたは平面図の壁面を指して実寸プレビューを確認し、クリックして配置します。残り数量が2点以上の場合は「まとめて配置」から点数・列数・縦横の間隔を指定し、行列全体をプレビューしてクリック1回で一括追加できます。重なる位置や全体が収まらない壁は赤く表示し、一部だけの追加は行いません。「数量（配置上限）」を各プランの上限とし、単品は1、複数枚は総数まで配置できます。Escで追加を中止します。
3. 作品を3Dまたは平面図で選択。右側で壁面・壁面起点から中心までの距離・床からの下端高さを入力します。入力はEnterまたはフォーカス移動で確定します。作品中心高も表示されます。
4. 3D・平面図の配置済み作品は、ドラッグして別の壁面や可動壁の表裏へ移せます。同じ壁面で複数選択し、選択済み作品を通常ドラッグすると、間隔・左右の並び・高さの差を保ったまま全作品をまとめて移動できます。指した壁に沿う緑のプレビューで離すと確定し、1点でも他作品と重なる赤い位置や全体が収まらない壁では元に戻ります。Escで中止。通常10 mm、Altで1 mm刻みです。壁端・床・天井にはグループ全体を収めます。「作品を正面から確認」で拡大できます。
5. Shift/Ctrl＋クリックで複数選択し、右側の「選択作品の整列」で左端・左右中央・右端・上端・上下中央・下端を揃えます。「均等配置」は横方向・縦方向を切り替え、両端を固定するか、作品間のすき間をmmで指定します。「行列に並べる」では列数と列・行のすき間を指定できます。同じ壁面の作品が対象で、均等・行列配置は1点選択時にその壁の全作品が対象です。詳しくは [整列・均等・行列配置](docs/ARTWORK-PLACEMENT.md#整列均等行列配置) を参照してください。
6. 「プラン」タブで現在のレイアウトを複製・改名し、別案を作ります。比較プランを選ぶと、平面と3Dに紫の輪郭を重ねます。建築・配置ライン・作品一覧は全プランで共通、可動壁と作品配置はプランごとです。
7. 「歩く」でWASD移動、ドラッグで視線移動、左右矢印で旋回、Shiftで速度変更。目線高さは右下で変更できます。壁・柱・可動壁の衝突を判定します。Escで俯瞰へ戻ります。
8. 「可動壁」タブの「＋ 可動壁を追加」で追加モードに入り、3Dまたは平面図の点線の配置ラインを指すと、その位置・方向に幅3,000 × 高さ5,000 × 厚み200 mmの壁を半透明でプレビューします。クリックで確定、Escまたは「追加を中止」でキャンセル。通常10 mm、Altで1 mm刻みです。ラインの端では壁全体が収まる位置に調整し、天井高・建築範囲に収まらない位置は赤く表示して追加できません。床ラインを非表示にしていても追加中は一時表示します。配置後は平面・3Dでドラッグするか、起点から壁中心までのmm座標で移動できます。作品の＋を押して可動壁の表面・裏面へポインターを向け、クリックで配置すると、壁の移動・向き変更に追従します。壁はプランごとに保存され、複製時には数量上限の範囲内で両面の作品配置も複製されます。超過する場合は複製を拒否します。
9. 「配置ラインの座標を編集」で点線の始終点をmm単位で修正・追加できます。初期ラインはPDFの相対位置を参考にした推定です。PDF上の線長を1/100として実寸に換算していません。ラインは建物内の水平・垂直線とし、実測座標を得たら置き換えてください。
10. 平面図・3Dの作品や可動壁、鉄骨フレーム・ライン・膜を右クリックするとメニューを表示します。作品は作品名・作家・実寸を確認でき、「作品情報を表示」で制作年・数量・梱包・備考などの登録情報を開けます。「作品の配置を削除」はこのプランのその1点の配置だけを解除し、作品ライブラリは保持します。可動壁は確認後に両面の作品配置も含めて削除します。鉄骨はフレーム1組またはライン1本を削除し、膜の内部では「この面の膜を削除」で骨組みを残して膜だけを外せます。境界ラインの削除時は、そのラインを使う膜も削除します。Ctrl+Zで元に戻す、Ctrl+Shift+Z / Ctrl+Yでやり直し（40操作分）。一括追加も1回で取り消せます。Deleteでも作品の配置を解除できます。作品自体の削除は編集ダイアログから実行し、全プランの配置を解除します。
11. 画面下の「作品情報」で作品脇のラベルをON/OFFし、「表示項目」で作品名・作家・実寸などを選びます。設定はプロジェクトに保存されます。詳しい操作と制約は [作品の数量・配置・情報ラベル](docs/ARTWORK-PLACEMENT.md) を参照してください。
12. 作品欄の「画像付き」「一覧（画像なし）」で表示を切り替えます。一覧は画像を読み込まず、作品名・作家・実寸・配置数と操作をコンパクトに表示します。検索・編集・単品／まとめて配置は両方で利用できます。
13. 画面下の「梁」「中二階」「照明レール」は独立してON/OFFできます。3D・平面・並べる・歩行へ切り替えても保持し、再読み込み・JSON・GitHub保存にも引き継ぎます。照明レールの表示OFFでは灯具の形状を隠し、点灯・照度の設定は保持します。点灯の切り替えは「照明・日照」で行います。

### 寸法指定の形状と人物シルエット

- 左の「形状・人」→「形状」で、ボックス・平面・机・円柱・球／楕円体・多角形を選び、幅・高さ・奥行をmmで指定して追加します。平面は垂直／水平を切り替えられます。多角形は枠内を順にクリックして輪郭を描き、指定した幅・奥行・高さに合わせて立体化します。交差した輪郭は登録できません。
- 「人物シルエット」では、提供された `人型シルエット.svg` の11人を個別に選択できます。グレー・初期透明度50%。身長と透明度（0%=不透明、100%=透明）を変更でき、縦横比と床面0 mmの足元位置を保ちます。人物は向きを持つ両面の輪郭で、背景の四角形はありません。
- 追加位置は主室中央です。平面図・3Dでドラッグして移動し、右の詳細で位置X/Z・回転を指定します。形状は床からの高さ・色も指定できます。通常10 mm、Altで1 mm刻み。配置済み一覧からも選択でき、「3Dでこの配置を見る」で拡大します。複製・削除・右クリック削除・元に戻す／やり直すに対応します。
- 形状・人物はプランごとに独立して保存され、プラン複製・比較表示・ブラウザー保存・JSON・GitHub保存・GLB出力へ含まれます。建物外への配置も可能です。形状上への作品設置や、形状・人物との歩行衝突判定は含みません。
- 分割済みSVGは `public/silhouettes/person-01.svg` 〜 `person-11.svg`。元の輪郭は `src/silhouettes.json` にも保持します。提供SVGの分割を再実行する場合は `node scripts/split-silhouettes.mjs "元SVGのパス"` を使います。一般的なDXFファイルのインポート機能ではありません。

画面上部の「作品パネル」「詳細パネル」で、左右のパネルを個別に折り畳み、ビューを広げられます。開閉状態はこのブラウザーに保存されます。

「平面図を別窓で」で独立した平面図ウィンドウを開けます。ホイールまたは＋／−でズームし、背景のドラッグ、Space＋ドラッグ、中ボタンドラッグ、または「パン」をONにしてドラッグすると平行移動します。「全体を表示」で表示を戻せます。作品の選択・移動・元に戻す／やり直すはメイン画面と連動します。別窓を閉じてもメイン画面のデータは保持されます。ポップアップがブロックされた場合は、このサイトのポップアップを許可してください。

## 保存・設営・他ツールとの連携

- 「作品リスト・保存」：未配置も含む全作品を表で確認・編集できます。「作品リストCSVを保存」は表計算用のUTF-8 BOM付きCSV、「作品リストJSONを保存」は画像・全入力項目付きの `.ma-artworks.json` を出力します。「作品リストJSONを開く」で作品だけを追加・更新でき、建築やプランは保持します。同じIDは更新、それ以外は追加されます。取り込みはUndoで取り消せます。CSVは閲覧・表計算用で、アプリへの読み戻しにはJSONを使用してください。
- 提供された@KCUA作品の14行を解釈し、上坂の小品を200×300・300×400・400×500 mmの3サイズへ分けた16項目として登録します（既存サンプル4件は保持）。厚みはすべて40 mm。複数枚は点数と1枚あたりの寸法を分け、上坂の新作6枚は3列×2段・間隔なしの全体4800×2360 mmとして記録します。梱包は幅・高さ・奥行・数量・概寸／上限の数値項目に分解し、すべてmmで保存します。
- 合田の花5点は6〜8号の各点の内訳・号種が未指定のため、F8横455×380 mmを配置用の**仮寸法**に採用しています（[メーカーの号数表](https://daigakuframe.co.jp/products/size)）。確定寸法ではありません。上坂の小品は**概寸**、点数は未定です。三橋の「出す作品たち」だけは、ユーザー指定どおり「色々（0号程度から20号程度）」と実寸未入力を維持しています。
- 四曲屏風は1点・4面構成の「自立」、巻物2点は長机への「机上・平置き（案）」で登録しています。現在の配置機能は壁面展示に対応し、「自立」「机上・平置き」は一覧で管理します。画像未登録の壁面作品は無地で3D表示します。
- 前回の14件を登録済みの保存データにも、未編集の初期値だけ今回の解釈を反映します。手入力済みの寸法・メモ・配置や削除した作品は保持します。
- 操作後400 msでIndexedDBに自動保存。「保存済み」を確認して終了してください。ブラウザーデータを消すと消えるため、JSONも定期的に保存してください。
- 「書き出す」：画像・建築・全プランを含む `.ma.json` を保存。「開く」で復元。取り込み前の状態はUndoで回復できます。
- プランタブの「全プランの設営CSV」：壁面ID、作品実寸、壁面起点距離、下端・中心高さ、世界座標を出力。Excelで扱いやすいUTF-8 BOM付きです。
- 「現在の空間をGLB保存」：現在の建築・作品を**メートル単位**の3Dモデルとして出力。Blenderでは「ファイル > インポート > glTF 2.0」で取り込みます。Blenderはアプリ起動に不要です。JSONが編集の正本、GLBは他ツールでの表示・加工用です。外壁は内側だけ表示する面で、施工用のソリッドモデルではありません。
- ツールバーのカメラアイコン：現在の3DビューをPNG保存。
- 通常の編集・自動保存はブラウザー内で処理します。GitHubへの送信は「クラウド保存」で保存を実行したときだけ行い、画像を含むプロジェクト全体を送ります。外部フォントやCDNには依存しません。

### GitHubへのクラウド保存とURL共有

1. 「クラウド保存」を開くと、このリポジトリの保存リストが表示されます。公開データの読み込みにログインは不要です。
2. 保存するときは「GitHubでログイン」を押し、GitHubの画面で本人確認とアプリの承認を行います。トークンの作成・入力、保存先の入力は不要です。このリポジトリに書き込み権限のあるアカウントだけが保存できます。
3. 「別名で保存」で `nbbbnbbb/exhibition-simulator` の **`ma-saves` ブランチ**の `ma-projects/*.ma.json` へ、画像・建築・全プラン・表示設定を保存します。アプリのソースを置く `main` は更新しません。保存名が同じでも別名保存は別ファイルになります。
4. 保存リストの「開く」で読み込みます。直前の状態はUndoで戻せます。新規保存・読み込みの成功後はURLへ保存先が自動で付き、「URLをコピー」で共有できます。他の端末と共有するときは公開版からコピーしてください。
5. 「上書き保存」は同じURLを維持し、アクセス時に最新の保存を開きます。GitHubへの保存は手動です。他の端末の更新と競合した場合は拒否します。必要なら先に「別名で保存」で編集を保管してから、一覧を開き直してください。

このリポジトリは公開のため、**保存した作品情報・画像と過去の保存履歴も公開**されます。公開できない内容は保存しないでください。認証情報はタブのメモリーだけに保持し、プロジェクト・URL・ブラウザーストレージへ保存しません。終了・再読み込み・期限切れ後は再びGitHubでログインします。

管理者は利用開始前に [GitHubログインの設置手順](docs/GITHUB-SIGN-IN.md) に沿って、GitHub AppとVercelの認証サーバーを設定します。GitHub Pagesへ共通の書き込みトークンやClient Secretを埋め込む方式には対応しません。未設定時は保存を無効にし、保存リストの読み込みとJSON書き出しを利用できます。

画像込みで1保存80 MB以内、保存フォルダーは1,000項目未満に対応します。リストの日付はファイルの**作成日時**です。上書きで作成日時は変わりません。以前の共有URLの公開データも読めますが、新しい保存先はこのリポジトリの保存専用ブランチに固定します。

日照・照明の設定、概算照度の計算方法と制約は [日照・照明シミュレーション](docs/LIGHTING.md) を参照してください。

可動壁ラインと天井の梁・レールの対応は [天井構成](docs/CEILING.md) を参照してください。

「鉄骨」タブで矩形・ボックス・門形・三角形の軽量鉄骨フレームを追加し、平面図・3Dで自由に移動できます。外寸・位置・回転角・C形／U形／角パイプ／L形断面を指定でき、独自の組立形状・部材断面も登録できます。ビニール膜は面ごとに貼り、色・不透明度を変更できます。プランごとの保存、Undo / Redo、JSON・GLB出力に対応します。操作と制約は [軽量鉄骨フレームとビニール膜](docs/STEEL-FRAMES.md) を参照してください。

「作業平面を配置」から、まず仮想平面をドラッグ・XYZハンドルで配置し、位置を確定してから始点・終点をクリックして鉄骨部材を描きます。平面の中心は既存鉄骨に、ラインは建物・鉄骨の端点や辺に吸着します。「スナップ」と「直交モード」は個別にON/OFFを切り替えられます。平面の向き・位置を変えて立体的につなぎ、XYZ座標も編集できます。鉄骨フレームとラインは建物外・床下・天井の上にも配置可能です。同じ平面でラインを閉じると面が自動生成され、面ごとに膜を貼り、色・不透明度を変更できます。詳しくは [3Dでラインを描く](docs/STEEL-FRAMES.md#3dでラインを描く) と [ライン面の膜](docs/STEEL-FRAMES.md#ラインから生成した面に膜を貼る) を参照してください。

| 梁せい / 幅 / 間隔 | 500 / 300 / 2,650 mm（推定） | 写真から仮定。配列を簡略化                                                                                            |
| 可動壁             |   **3,000 × 5,000 × 200 mm** | ユーザー指定。幅・高さ・厚みを編集可能                                                                                |
| 点線の配置ライン   |           **実寸座標は推定** | 可動壁が設置可能なライン。記載寸法のある領域に点線の相対位置を対応させた初期値。1/100換算ではない。全始終点を編集可能 |
| 中二階床高         |             3,000 mm（推定） | 床形状・手すり位置も仮定                                                                                              |
| 柱                 |             幅850 mm（推定） | 主室西側、南端から5,395 mmの柱中心。写真・図面線から仮配置                                                            |
| 東側開口           |       起点4,750 / 幅1,500 mm | 図面の括弧付き寸法を暫定採用                                                                                          |
| 東南側出入口       |           幅2,057 mm（推定） | 西扉から転用。位置も仮定                                                                                              |
| (2,500) / 3,650 mm |                   解釈未確定 | 2,500は拘束に未使用。3,650は南中二階の仮配置に使用                                                                    |

**PDFデータが厳密な1/100で作られているとは仮定していません。** 文字で記載された数値寸法を優先し、線の座標や印刷サイズから実寸を確定しません。寸法列の基準点・対象範囲の解釈が未確定なので、全長・幅基準線・天井高・柱位置を現地で実測してください。左右の合計差を、図面の誤りとは断定していません。初期値を確定測量モデルと扱わないでください。「建築・寸法データ > 採用寸法を編集」から修正できます。相互に整合しない寸法は適用を拒否し、作品が収まらなくなる変更も拒否します。

3Dのワールド原点は主室北西内隅、+Xは図面右（東）、+Zは図面下（南）、+Yは上。保存値はmm、Three.jsの表示値はm。壁面起点はA/B/D/H/Iが北から南、C/E/F/Jが西から東です。図面上端を真北として扱います（ユーザー指定）。

## VR

Three.jsのWebXRを利用し、`local-floor` 基準、リグの拡縮なしで **1 m = 実空間1 m** としています。

- PC接続HMD：対応するOpenXRランタイム・WebXR対応ブラウザーから、localhost / 127.0.0.1で開きます。
- Quest等の単体HMD：上記のGitHub Pages公開URLをヘッドセットの対応ブラウザーから開きます。HTTPSで配信します。LANのHTTPだけでは通常WebXRを開始できません。
- トリガーを押して床へ向け、離すとテレポート。左スティックで前後、右スティックで30°旋回。床・柱との判定を使用。
- HMDのトラッキングが実際の目線高さを決めます。右の「目線高さ」は通常の歩行モード用です。
- **実機HMDの装着、VRでの操作感・1:1寸法の体感検証は未実施**です。対応APIがないPCでの案内表示は検証済みです。

技術参照：[Three.js WebXR](https://threejs.org/manual/pages/webxr-basics.html) / [WebXRManager](https://threejs.org/docs/pages/WebXRManager) / [Vite](https://vite.dev/guide/)。

## 残る制約

- 寸法の解釈が未確定なので、正確さを保証できるのは採用寸法に対する計算・表示の整合です。実際の建物との一致は実測後に確認します。
- 中二階は観察用の簡略形状。上階歩行、階段、外部、立体作品、斜めの配置ライン、曲面壁には未対応。
- 自然光・スポット・レール定常光と簡易照度概算に対応しています。実測照度、IES/LDTによる器具配光の再現、多重反射・実際の色校正は未対応です。詳細は [日照・照明の制約](docs/LIGHTING.md) を参照してください。
- 歩行衝突は室内境界・柱・可動壁に対して行い、扉から建物の外には出ません。天井下の局所高さ判定、手すり・作品との身体衝突は未対応。可動壁同士・柱・推定中二階との干渉は警告します。主室の梁・照明との局所干渉は未判定で、現地確認が必要です。
- プロジェクトはブラウザー内に1つ。GitHubの保存リストまたはJSONで複数案件を切り替えます。GitHub保存は手動で、複数ユーザーのリアルタイム共同編集には対応しません。
- 作品画像の色・トリミング・余白は画像そのまま、指定した外寸比率に伸縮。透明部分は白へ変換されます。
- GLBの外壁は片面の展示面です。3D外側から壁を透かすことで俯瞰編集を容易にしています。壁厚設定は平面表示用です。
